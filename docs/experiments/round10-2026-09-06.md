## What it found

- **A server error mid-response parks the unit, and its silence halts the
  hour** (#69). #62's second unit was ninety seconds in when the API
  answered `Server error mid-response`. The build stage parked it as a
  failure; a person retried it. The aborted prompt reported no usage, the
  meter counted an unmetered run and refused every start until 11:00 —
  by round 1's rule, correctly. Nine minutes here; up to fifty-nine.
- **The planner assigns tiers.** It put #62's reviewer-gate builder on
  `opus[1m]` — $4.70 and 4.49M tokens for a unit Sonnet built beside it for
  $2.29 — and nothing else. Allowed by the plan node's `model`, on the
  record before the run, and the first time the planner spent above the
  box's tier on its own judgement. Whether a node may name a tier above the
  box's is a policy question this round only raised.
- **The hourly volume cap is now the pace.** The five later units read
  14M to 25M tokens each with #55's narrowing in force; #63's unit read
  25.29M in fifteen minutes and closed the hour by itself. From 12:00 the
  round ran one unit an hour. The cap is a brake on a runaway and a round
  is not one; where it sits from here is the operator's dial.
- **Every unit named the daemon section.** Five of five, and #65's unit
  named none, which is the whole repository; the round was serial by
  construction and a whole-repository unit holds the sections it has
  collected while it waits for the rest. Nothing ran beside anything.
- **The reading material is still most of the repository.** A unit naming
  `loop` and `daemon` is granted fourteen packages and `cmd`; the contexts
  reached 229K to 250K. The grant is real since #55 and it is still the
  union of broad sections, not the paths a unit will touch.
- **The check that lands is not the check that promotes** (#68, from round
  9's promotion this morning). With the box landing on `main` the gate's
  check becomes the last check.
