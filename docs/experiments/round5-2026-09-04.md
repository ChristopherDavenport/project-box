## What the transcripts say about the cache

Per-request usage from the three Claude Code transcripts:

- Every request's context is a cache read. Cost is, to a close approximation,
  the sum of context over requests at 0.1×, plus each new token written once
  at 2× (the harness uses only the one-hour TTL; it exposes switches to
  disable caching and none to shorten it), plus output.
- The stable 25K of the harness prefix is a cache hit ACROSS sessions: the
  planner's first request wrote 41K cold; each unit's first request read
  24.7K and wrote 16K. The 16K that varies is the working directory, git
  state, and the brief.
- Context grew about 3K tokens per request, almost all tool output.

Resuming a session for the next unit, or forking the planner's session into
each unit, costs MORE at these prices: the inherited context is re-read on
every later request. Had the loop unit resumed the forge unit's session it
would have started at 185K and re-read about 11M tokens over its 52 requests,
$3.36 in reads alone against the $2.63 it paid for reads and writes together.
Reuse only pays if it also removes more than half the requests.

## Levers, ranked

1. Fewer requests: several reads per request, precise file pointers from the
   planner. A third fewer is about $2 of $9.
2. Slower context growth: ranged reads, quiet test output. About $1.
3. Effort `high` instead of `xhigh`: fewer, more consolidated calls and less
   output. Round 6's configuration (box.yaml `roles`).
4. A computed repository map for the planner, which spent 29 Bash calls
   discovering the tree. Deterministic; no agent on the intake path.
5. Haiku for trivial units through the plan node's `model` field, unused so
   far.

Not levers: session resumption or forking (above); context editing (rewrites
the cached conversation); the model's window (Sonnet reports 1M too — the
unit's narrowness is what bounds the re-read, not the window).

## What Gas City does about the same arithmetic

Nothing different per request. It runs on metered upstreams — API key,
Bedrock, a gateway — where there is no window to run out of, only a bill;
idle agents make no calls (pools scale to zero, patrols back off, sessions
sleep); every patrol iteration and every worker task is a short session over
a bounded context; and mechanical duties are exec orders. This factory now
has the same shape. The difference is the credential, which is still to be
decided: on an API key `max_cost_per_window` is the real brake and it is
already enforced.
