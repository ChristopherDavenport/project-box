## What effort buys

Round 6's planner, on the same repository the day before at `xhigh`, is the
closest pair: 53 requests and 34 tool calls there, 55 and 32 here. Effort
did not change how many times the agent went to the model or how many
tools it reached for. It changed what each request produced:

| per request | round 6 planner (xhigh) | round 7 planner (high) |
|---|---|---|
| output tokens | 663 | 359 |
| wall | 8.7 s | 4.5 s |
| cost | $0.027 | $0.026 |

Half the output, half the time, the same money — because the money is not
in the output. Cache reads were 46% of round 6's bill and are 62% of this
one; the unit here read 11M tokens of its own context to produce 42K. The
lever effort pulls, output, was the smallest term. The levers it does not
touch, request count and context size, are the bill.

The unit was the round's cost. One unit for two sections meant one context
carried both halves: 174K by the end, against 124K and 92K for round 6's
two halves of the same shape, and 160 requests against 91 and 73. A plan
that names two sections in one node has traded the section lease's
parallelism and the context ceiling for one handoff fewer. Whether that
trade is right is the planner's judgement to make; that it costs is now on
the record.

## What the round found beside that

**The untitled rows were the runtime's, not the adapter's.** The planner's
run log held 32 tool calls and one title on a binary that carried #44's
late-title fix. Three captures of the adapter's raw wire showed titles on
every call, placeholder first and the proper one after. The runtime's wire
struct typed an update's `content` as the message chunk's object; on a tool
call it is a list; the decoder's type error made the handler drop the whole
event, and a notification's error goes nowhere on the wire. Every titled
update the adapter sent with content, and every completion, vanished
without a record. #48 decodes content by shape, counts an update that still
fails to parse on the agent-result record, and gives a call a frame per
title. The round-6 write-up's explanation is corrected there.

**The planner's frames reached the run log**, under `plan-<ingress>`,
which is the half of #47 that #44 built; the unit built the other half.

## Levers, ranked

1. Request count and context growth, unchanged from round 5 and now with
   the arithmetic to prove it: 98% of the tokens and 62% of the bill were
   the context re-read. Batched reads and precise pointers from the
   planner's handoff are still the cheapest change.
2. Sectioned units over multi-section units. The planner decides; the
   planner's prompt should say what a second section in one node costs.
3. Effort `high` stays. It halved output and wall time at no cost in
   requests; `xhigh` bought nothing this repository could see.
4. The unsectioned unit's check (#46) and the meter's start accounting
   (#45): small, and both bit round 6.
